# Формирование sitemap.xml

Как строится `sitemap.xml` в этом проекте (Next.js Pages Router).

## Почему не статический файл

Набор маршрутов меняется вместе с кодом, а держать его вторым списком в `public/sitemap.xml`
означает гарантированно про него забыть. Поэтому карта собирается на лету из того же
источника, что и роутинг, — файловой системы `src/pages`.

`/sitemap.xml` отдаётся через `getServerSideProps`
([`src/pages/sitemap.xml.ts`](../src/pages/sitemap.xml.ts)) с
`Cache-Control: public, s-maxage=86400, stale-while-revalidate` — сама сборка дешёвая
(обход каталога, без сетевых запросов), а заголовок снимает нагрузку на прокси.

## Что попадает в карту

[`scan-pages.ts`](../src/shared/api/sitemap/scan-pages.ts) обходит `src/pages` и собирает
статические маршруты. Исключаются:

- служебные файлы: `_app`, `_document`, `_error`, `404`, `500`, `robots.txt`, `.keep`;
- каталог `api/` и всё, что начинается с точки;
- динамические сегменты (`[slug]`, `[...rest]`) — публичных URL с параметрами в проекте нет:
  лента одна, отдельных страниц у событий GCN не заводится;
- файлы, оканчивающиеся на `.xml` (сам sitemap).

`index.tsx` превращается в путь каталога (`/`, `/about`), остальные файлы — в путь по имени.

Появится раздел с динамическими URL — обход придётся дополнить источником этих URL
(запрос в БД), а не расширять эвристику по файлам: путей, которых нет в файловой системе,
она не увидит.

## Сборка и рендер

[`build-sitemap.ts`](../src/shared/api/sitemap/build-sitemap.ts) превращает пути в абсолютные
URL по `siteURL.origin` (из `NEXT_PUBLIC_SITE_URL`);
[`render-xml.ts`](../src/shared/api/sitemap/render-xml.ts) собирает XML и **экранирует**
`&`, `<`, `>` — неэкранированный амперсанд в URL делает документ невалидным целиком, и карту
отбрасывает весь парсер, а не одну запись.

`lastmod` в записи опционален (`SitemapEntry.lastmod`) и сейчас не заполняется: у статических
страниц нет содержательной даты изменения, а подставлять время сборки — вводить поисковик
в заблуждение на каждом деплое.

## Проверка

```bash
curl -s localhost:3000/sitemap.xml | head
```

Ожидаемо: `<?xml …?><urlset …><url><loc>https://…/</loc></url>…`. Пустой `<urlset>` означает,
что `scanPages` не нашёл `src/pages` — проверьте рабочий каталог процесса (`process.cwd()`).
