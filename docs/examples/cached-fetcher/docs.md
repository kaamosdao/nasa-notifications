# Кеш с тегами + ISR-инвалидация

Эталоны вынесены из боевого проекта **sozdateli** — там кеш прошёл продакшен и оброс решениями,
которых в сборке пока нет. Файлы самодостаточны (компилируются), это образец для переноса, а не
подключённый код.

| Файл | Что показывает |
|---|---|
| [cache-tags.example.ts](cache-tags.example.ts) | Теги + карта `модель Strapi → теги` |
| [cached-fetcher.example.ts](cached-fetcher.example.ts) | `cached()` с тегами, `invalidateTags()`, обёртка `cachedFetcher()` |
| [isr-revalidate.example.ts](isr-revalidate.example.ts) | Карта ISR-путей + вебхук, сбрасывающий **два слоя** |

Скилл: `caching-and-isr`. Механика lru-cache: [docs/11-server-cache.md](../../11-server-cache.md).

## Что уже есть в сборке, а что берём из sozdateli

| Возможность | В сборке (`src/shared/api/cache.ts`) | В sozdateli |
|---|:--:|:--:|
| `cached()` (SWR + single-flight + устойчивость к падению CMS) | ✅ | ✅ |
| `invalidate(key)` / `invalidateAll()` | ✅ | ✅ |
| Инвалидация по модели из вебхука | ✅ карта `MODEL_CACHE_KEYS` (ключи) | ✅ **теги** (many-to-many) |
| **Теги** + `invalidateTags()` | ❌ | ✅ |
| **`cachedFetcher()`** — подключение кеша переименованием функции | ❌ | ✅ |
| **ISR** + `res.revalidate()` по путям | ❌ (проект на 100% SSR) | ✅ |
| Аварийный выключатель `STRAPI_CACHE_DISABLED` | ❌ | ✅ |
| TTL по умолчанию | 60 сек | **неделя** (свежесть держит вебхук, а не TTL) |
| `max` записей | 200 | 500 |

## Три идеи, ради которых это вынесено

### 1. Теги вместо «модель → один ключ»

Один справочник (иконки, контакты) раскрывается сразу в нескольких источниках (шапка **и**
подвал), а одна коллекция влияет на несколько подсистем (проекты = меню + sitemap + контент).
Связь many-to-many ключами не выражается — нужны теги.

Правило выбора по умолчанию: **лишний сброс дёшев** (один перезапрос, и данные снова живут неделю),
**пропущенный дорог** (устаревший контент провисит весь TTL). Поэтому неизвестная модель сбрасывает
всё.

### 2. TTL — не механизм свежести

В sozdateli TTL = **неделя**, а актуальность обеспечивает вебхук. TTL здесь — только страховка от
пропущенного вебхука и предохранитель от вечного протухания. Это переворачивает привычную настройку:
не «подберём TTL, чтобы правки появлялись за N минут», а «правки появляются мгновенно по вебхуку,
TTL — аварийный сценарий».

### 3. Два слоя кеша, и порядок сброса обязателен

При ISR кешируются **данные** (LRU) и **готовый HTML** (кеш ISR). Одно без другого не работает:

```
СНАЧАЛА invalidateTags(...)   → сбросили данные
ПОТОМ  res.revalidate(path)   → регенерация читает уже свежие данные
```

Обратный порядок закрепляет старое: регенерация прочитает старые данные из LRU и запишет их
в статику **на весь срок ревалидации** — «сброс» зафиксирует ровно то, что мы пытались обновить.

## Подводные камни, отмеченные в боевом коде

- **Карта тегов обязана лежать в `globalThis`.** Страницы и API-роуты Next компилирует в разные
  бандлы — у модульной переменной в эндпоинте сброса карта окажется пустой. Вебхук ответит
  `200 OK, removed: 0` и не сбросит ничего, притом что кеш полон. Ошибка полностью тихая.
- **Ключ обязан включать все параметры.** Фетчер «принимает только status» может иметь второй
  аргумент (slug, вариант страницы) — если он не попал в ключ, страницы молча отдают контент
  друг друга.
- **Нельзя кешировать недетерминированные фетчеры** — те, что материализуют случайное значение
  (позиция рекламного блока, порядок выдачи) или читают текущую дату: значение застынет на весь TTL.
- **В карту ISR-путей пишем только реально переведённые на `getStaticProps` роуты.**
  `res.revalidate()` по SSR-адресу вернёт ошибку и зашумит лог.
- **Переименование slug даёт два пути** — новый построить, старый ревалидировать, иначе прежний URL
  продолжит отдавать страницу из статики.
- **`Promise.allSettled` при ревалидации путей** — удалённый или ни разу не собранный путь не должен
  отменять остальные.
- **`notFound` на любую ошибку в ISR — ловушка**: авария Strapi покажется как «страница не найдена»
  и **закешируется** на живом адресе до следующей ревалидации. В sozdateli для этого есть
  `assertSourcesAlive(failedRequests, [...])`.
- **Читаешь куки — ставь `private, no-cache`.** Ответ, собранный по куке, нельзя отдавать в общий
  кеш (nginx/CDN): следующий посетитель увидит чужое избранное. У них для этого
  `shared/lib/cache-headers.ts` (`setPrivateNoCache` / `setPublicCache`).

## Двухуровневое кеширование: не оборачивать дважды

В `getCommonData` из sozdateli часть источников кешируется **внутри себя** (`cachedFetcher` со
своими тегами), поэтому снаружи их не заворачивают повторно:

> Второй слой здесь только плодил бы записи и расходился с инвалидацией: сброс тега достал бы
> внешнюю копию, но не внутреннюю.

Каждый источник — свой ключ и свой тег: правка подвала не должна сбрасывать шапку, иначе один
вебхук обнуляет весь прогрев.
